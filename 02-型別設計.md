# 02 型別設計：class、record、struct 與 properties

## 學習目標

- 從 Java class / field / getter-setter 的思維轉讀 C# type design。
- 分辨 `class`、`record class`、`record struct`、`struct` 的語意。
- 看懂 `get`、`set`、`init`、`readonly`、`const`、`sealed` 與 object initializer。

## 1. 一句話理解

C# 把「資料形狀」與「物件行為」用較少樣板表達；`record` 偏資料與 value equality，`class` 偏 identity、state 與 behavior，而 property 是 C# 對外暴露資料存取規則的主要語法。

## 2. Java 對照

### field 與 constructor injection

Java：

```java
private final UserService userService;

public UserController(UserService userService) {
    this.userService = userService;
}
```

C#：

```csharp
private readonly IUserService _userService;

public UserController(IUserService userService)
{
    _userService = userService;
}
```

`final` 與 `readonly` 的核心關係是：欄位只能在 declaration / constructor 初始化，不能在之後重新指向另一個物件。它不代表被指向的 object 一定 immutable。

### Java bean vs C# property

Java 常見：

```java
private String name;

public String getName() { return name; }
public void setName(String name) { this.name = name; }
```

C#：

```csharp
public string Name { get; set; } = string.Empty;
```

C# property 不是單純 public field；它可有 getter / setter 的不同 accessibility，也可放 validation 或計算邏輯。

## 3. C# 語法

### class、interface、abstract、sealed

```csharp
public interface IUserRepository
{
    Task<User?> FindByIdAsync(Guid id, CancellationToken cancellationToken);
}

public abstract class Entity
{
    public Guid Id { get; init; }
}

public sealed class UserService : Entity
{
    // sealed class 不能再被繼承。
}
```

- `interface`：contract；class 或 struct 可以實作多個 interface。
- `abstract`：不能直接 new，通常提供共用實作或要求 derived class 實作 abstract member。
- `sealed`：停止 inheritance；常用於不希望被 override、或單純表示完整 concrete implementation 的 service。

### properties：`get`、`set`、`init`

```csharp
public sealed class User
{
    public Guid Id { get; init; }
    public string Name { get; set; } = string.Empty;
    public DateTimeOffset CreatedAt { get; init; }
    public bool IsActive { get; private set; } = true;

    public void Deactivate() => IsActive = false;
}

var user = new User
{
    Id = Guid.NewGuid(),
    Name = "Ada",
    CreatedAt = DateTimeOffset.UtcNow
};

// user.Id = Guid.NewGuid(); // init-only，初始化完成後不能再設。
user.Name = "Ada Lovelace"; // set，可在建立後修改。
// user.IsActive = false; // private set，只能在 User 內修改。
user.Deactivate();
```

```csharp
public sealed record UserDto(Guid Id, string Name, DateTimeOffset CreatedAt);
```

`init` 允許 constructor 或 object initializer 設值，但 object 建立完成後不可再設；它很適合 DTO、configuration、immutable-like data。

### record、record class、record struct

```csharp
public record UserDto(Guid Id, string Name);
// 等同於 record class；是 reference type，預設 value equality。

public record class UserDtoExplicit(Guid Id, string Name);

public record struct Money(decimal Amount, string Currency);
public readonly record struct Coordinates(double Latitude, double Longitude);
```

- `record` 是 `record class` 的 shorthand。
- `record class` 保留 reference semantics，但 compiler 產生 value-based equality、可讀的 `ToString()` 與 `with` copy。
- `record struct` 是 value type，適合小型 value object；不要因為它短就拿來當所有 DTO。
- `readonly record struct` 進一步表達不可變的 value semantics。

```csharp
var original = new UserDto(Guid.NewGuid(), "Ada");
var renamed = original with { Name = "Grace" };

Console.WriteLine(original == new UserDto(original.Id, "Ada")); // True
```

Entity Framework Core entity 通常不要直接改成 record 來追求簡短；entity 的 identity、tracking 與 reference behavior 和 record 的 value equality 不是同一個需求。DTO / command / result 是 record 的常見位置。

### struct

```csharp
public readonly struct Temperature
{
    public Temperature(double celsius) => Celsius = celsius;

    public double Celsius { get; }
    public double Fahrenheit => Celsius * 9 / 5 + 32;
}
```

`struct` 是 value type。它可以有 method、property、constructor，也可以實作 interface，但不能繼承另一個 class / struct。用在小型、值相等有意義、主要承載資料的 value object；大而可變的 struct 會因複製成本與 mutation 造成困惑。

### `const` vs `static readonly`

```csharp
public static class RetryPolicy
{
    public const int MaxAttempts = 3; // compile-time constant
    public static readonly TimeSpan DefaultTimeout = TimeSpan.FromSeconds(10);
}
```

`const` 只能放編譯期可決定的 primitive / string 等 constant，引用它的 assembly 可能把值 inline。需要 runtime 建立、或不希望被 caller 編譯時嵌入的值，用 `static readonly`。

## 4. 實務範例：domain entity 與 API DTO 分開

```csharp
public sealed class User
{
    public Guid Id { get; init; }
    public required string Name { get; set; }
    public string? PhoneNumber { get; set; }
    public DateTimeOffset CreatedAt { get; init; }
    public bool IsActive { get; private set; } = true;

    public void Deactivate() => IsActive = false;
}

public sealed record UserResponse(
    Guid Id,
    string Name,
    DateTimeOffset CreatedAt);
```

Entity 可以有行為、tracking state、private setter；response DTO 只表達 API contract。不要把 EF entity 直接當 public response，否則資料庫欄位、navigation property 或內部欄位可能意外暴露。

## 5. 常見誤解

- `record` 不等於 immutable value type；`record` 預設是 `record class`，仍是 reference type。
- `readonly` field 只阻止「重新指定欄位」，不會凍結 mutable object：`readonly List<int>` 仍可 `Add`。
- auto-property 不等於 field；compiler 會產生 backing field，外部只看到 accessor contract。
- `init` 不是 Java `final` 的完全等價物；它限制 property assignment 的時機，物件內部仍可能有 mutable 狀態。
- `sealed` 不代表 thread-safe，也不代表 immutable。
- `struct` 不是「比較快的 class」；它有 copy semantics，使用前先確認 value semantics。

## 6. 面試怎麼回答

> 我通常用 class 表示有 identity、行為或需要被 EF Core tracking 的 entity；用 record class 表示以資料為主、希望 value equality 與 `with` copy 的 DTO / command / result。`record struct` 是小型 value type。`init` 允許初始化時設定、之後不能再改；`set` 則允許物件建立後修改。`readonly` field 只保證欄位 reference 不會被重新指定，不會讓被指向的物件 immutable。

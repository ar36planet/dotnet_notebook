# 08 資源管理：`IDisposable`、`using` 與 `IAsyncDisposable`

## 學習目標

- 把 Java try-with-resources 對照到 C# disposal pattern。
- 讀懂 `using var`、`await using` 背後的 try/finally。
- 知道何時 application code 要負責釋放 stream、response、transaction 等資源。

## 1. 一句話理解

GC 只負責 managed memory，不保證檔案 handle、socket、DB transaction 等外部資源及時釋放；`IDisposable` / `IAsyncDisposable` 為資源 owner 提供確定性的 cleanup contract。

## 2. Java 對照

Java：

```java
try (InputStream input = Files.newInputStream(path)) {
    // use input
}
```

C#：

```csharp
using var input = File.OpenRead(path);
// use input
// scope 結束時自動 Dispose()
```

兩者都把 cleanup 放進類似 `finally` 的保證區段；C# 的 async resource 則使用 `await using` 對應 `DisposeAsync()`。

## 3. C# 語法

### `IDisposable` 與 using

```csharp
using (var stream = File.OpenRead(path))
{
    // read stream
}

using var anotherStream = File.OpenRead(path);
// current scope 結束時 Dispose()
```

概念上接近：

```csharp
var stream = File.OpenRead(path);
try
{
    // use stream
}
finally
{
    stream.Dispose();
}
```

### `IAsyncDisposable` 與 await using

```csharp
await using var transaction =
    await db.Database.BeginTransactionAsync(cancellationToken);

// async work
await transaction.CommitAsync(cancellationToken);
// scope 結束呼叫 DisposeAsync()
```

`DisposeAsync()` 回傳 `ValueTask`；當 cleanup 本身需要非同步 I/O 時使用。典型例子包括 async transaction、某些 network / stream resource。

### `try/catch/finally`、`throw`、custom exception

```csharp
public sealed class UserNotFoundException(Guid id)
    : Exception($"User {id} was not found.");

try
{
    var user = await _repository.FindAsync(id, cancellationToken)
        ?? throw new UserNotFoundException(id);
}
catch (UserNotFoundException)
{
    throw; // 保留原始 stack trace，讓上層 exception middleware 轉成 404
}
finally
{
    // 無論成功或失敗都會執行；不適合放會再次 throw 的主要業務流程。
}
```

在 ASP.NET Core 中，domain exception 到 HTTP status 的 mapping 通常集中在 exception handling middleware / `IExceptionHandler`，不要每個 controller 都複製一套 try/catch。

## 4. 實務範例：上傳或處理檔案

```csharp
[HttpPost("upload")]
public async Task<IActionResult> Upload(
    IFormFile file,
    CancellationToken cancellationToken)
{
    if (file.Length == 0)
    {
        return BadRequest("Empty file");
    }

    var path = Path.Combine(_storageRoot, Path.GetRandomFileName());
    await using var output = System.IO.File.Create(path);
    await using var input = file.OpenReadStream();

    await input.CopyToAsync(output, cancellationToken);
    return Ok(new { file.Length });
}
```

真實系統還要驗證副檔名、content type、檔案大小、檔名 path traversal、病毒掃描與儲存位置。重點是：request stream、output stream 都有 owner；誰建立或持有它，誰應清楚誰負責 dispose。

### 自訂 disposable type

```csharp
public sealed class TempFile : IDisposable
{
    private readonly string _path;

    public TempFile(string path) => _path = path;

    public void Dispose()
    {
        File.Delete(_path);
        GC.SuppressFinalize(this);
    }
}
```

非 sealed base class 的完整 dispose pattern 會再加入 `Dispose(bool)`；應用程式一般優先組合（cascade dispose）與 sealed class，除非真的需要管理 unmanaged resource 或允許繼承。

## 5. 常見誤解

- `Dispose` 不是釋放 managed memory；GC 仍由 runtime 管理。
- 不是所有拿到的 `IDisposable` 都由你 dispose；先確認 ownership。DI 建立並管理的 service 通常由 container 在 lifetime 結束時處理。
- `using var` 的 scope 是目前 block / method，不是整個程式。
- `IAsyncDisposable` 不會自動被同步 `Dispose()` 呼叫；需要 `await using` 或明確 `DisposeAsync()`。
- 不要把 `using` 加在由 `IHttpClientFactory` 管理 lifetime 的 typed client 上，除非你清楚自己擁有的資源。

## 6. 面試怎麼回答

> `IDisposable` 是同步 cleanup contract，`IAsyncDisposable` 是非同步 cleanup contract。`using` / `await using` 會在 scope 結束時以 try/finally 的方式呼叫 `Dispose` / `DisposeAsync`。它們主要保證檔案、socket、transaction 這類非 memory 資源可以及時釋放；不等於手動管理 GC。是否該 dispose 還要看 resource ownership。

## 7. 小練習

2. 判斷 `DbTransaction` 應使用 `using` 還是 `await using`。

# 15 綜合實作：Users Web API

## 學習目標

- 把前面章節的 C# 與 ASP.NET Core 知識串成一個最小但合理的 API。
- 看到 service code 時，能逐項說明每個 keyword 的設計意圖。
- 能把範例拆成 entity、DTO、repository、service、controller 與 composition root。

## 1. 一句話理解

這個範例把 `GET /api/users/{id}`、`GET /api/users/active` 與 `POST /api/users` 拆在 controller、service 與 repository，controller 只留路由與狀態碼。

## 2. Java 對照

| Spring Boot | ASP.NET Core | 備註 |
| --- | --- | --- |
| `@RestController` | `[ApiController]` + `ControllerBase` | API endpoint |
| `@Service` | scoped `UserService` | 使用案例與 DTO mapping |
| `@Repository`／JPA repository | `IUserRepository` + EF Core implementation | 資料存取邊界 |
| `ResponseEntity<T>` | `ActionResult<T>` | status code + body |
| `Optional<T>` | nullable `T?` | 找不到資料時回 null |
| JPA `findById` | `SingleOrDefaultAsync` | 查詢執行由 EF Core provider 處理 |

## 3. C# 語法：核心 code

### 先看會出事的地方

把查詢、驗證、資料庫寫入和 HTTP response 全塞進 controller，第一個 endpoint 也許能跑；加入第二個 endpoint 後，重複的規則和資料存取就會開始分叉。這個範例把責任切成：

```text
HTTP request
    ↓
Controller：路由、狀態碼、request / response contract
    ↓
Service：使用者規則與 DTO mapping
    ↓
Repository：資料存取
    ↓
EF Core / in-memory store
```

interface 只放在需要替換、隔離測試或代表外部邊界的位置；不是每個 class 都必須再包一層 interface。

以下是核心實作；完整可建置專案在 `examples/UserApi`，其中的 `InMemoryUserRepository`、`IClock` 與 `SystemClock` 另外放在對應檔案。

### Domain entity：`User.cs`

```csharp
namespace UserApi.Domain;

public sealed class User
{
    public Guid Id { get; init; }
    public required string Name { get; set; }
    public string? PhoneNumber { get; set; }
    public DateTimeOffset CreatedAt { get; init; }
    public bool IsActive { get; private set; } = true;

    public void Deactivate() => IsActive = false;
}
```

為什麼 entity 用 `class` 而不是 record？它有 identity、可變 state 與 behavior；這種語意通常比 record 的 value equality 更接近 persistence entity。

### DTO：`UserContracts.cs`

```csharp
namespace UserApi.Contracts;

public sealed record CreateUserRequest(
    string Name,
    string? PhoneNumber);

public sealed record UserResponse(
    Guid Id,
    string Name,
    DateTimeOffset CreatedAt);
```

DTO 使用 record 的理由：它是 API data contract，主要目的是攜帶資料、清楚表示欄位、支援 value equality / readable `ToString`，不需要 entity 的 mutable behavior。

### Repository contract

```csharp
namespace UserApi.Repositories;

public interface IUserRepository
{
    Task<User?> FindByIdAsync(
        Guid id,
        CancellationToken cancellationToken);

    Task<IReadOnlyList<User>> GetAllAsync(
        CancellationToken cancellationToken);

    void Add(User user);

    Task SaveChangesAsync(CancellationToken cancellationToken);
}
```

這裡回傳 `IReadOnlyList<User>` 而不是 `List<User>`，因為 repository 對 caller 的承諾是「一組已 materialize、可讀且有順序的結果」，而不是暴露內部 list implementation。

### Service：`UserService.cs`

```csharp
public interface IUserService
{
    Task<UserResponse?> GetAsync(
        Guid id,
        CancellationToken cancellationToken);

    Task<IReadOnlyList<UserResponse>> GetActiveAsync(
        CancellationToken cancellationToken);

    Task<UserResponse> CreateAsync(
        CreateUserRequest request,
        CancellationToken cancellationToken);
}

public sealed class UserService(
    IUserRepository repository,
    IClock clock) : IUserService
{
    public async Task<UserResponse?> GetAsync(
        Guid id,
        CancellationToken cancellationToken)
    {
        var user = await repository.FindByIdAsync(
            id, cancellationToken);

        return user is null ? null : ToResponse(user);
    }

    public async Task<IReadOnlyList<UserResponse>> GetActiveAsync(
        CancellationToken cancellationToken)
    {
        var users = await repository.GetAllAsync(cancellationToken);

        return users
            .Where(x => x.IsActive)
            .OrderBy(x => x.Name)
            .Select(ToResponse)
            .ToList();
    }

    public async Task<UserResponse> CreateAsync(
        CreateUserRequest request,
        CancellationToken cancellationToken)
    {
        if (string.IsNullOrWhiteSpace(request.Name))
        {
            throw new ArgumentException(
                "Name is required.", nameof(request.Name));
        }

        var user = new User
        {
            Id = Guid.NewGuid(),
            Name = request.Name.Trim(),
            PhoneNumber = request.PhoneNumber,
            CreatedAt = clock.UtcNow
        };

        repository.Add(user);
        await repository.SaveChangesAsync(cancellationToken);
        return ToResponse(user);
    }

    private static UserResponse ToResponse(User user)
        => new(user.Id, user.Name, user.CreatedAt);
}
```

這段就是目標 code 的逐項閱讀練習：

- `sealed`：此 service 不打算被繼承。
- `IUserService`：service contract；controller 依賴 abstraction。
- primary constructor parameters：C# 12 的簡潔 constructor injection 寫法。
- `Task<UserResponse?>`：非同步，且找不到 user 是合法的 null 結果。
- `IReadOnlyList<UserResponse>`：呼叫者只能透過這個 contract 讀取 list 形狀。
- `CancellationToken`：讓 request cancellation 可以傳進 repository。
- `Where / OrderBy / Select / ToList`：先篩選、排序、映射 DTO，最後 materialize。
- `ToList()`：此處把 repository 結果轉成一份 list snapshot；若 repository 是 EF Core，execution point 要另外看 `ToListAsync()`。
- `DateTimeOffset`：讓建立時間帶有明確 offset / UTC 語意。

### Controller：`UsersController.cs`

```csharp
[ApiController]
[Route("api/users")]
public sealed class UsersController(IUserService service)
    : ControllerBase
{
    [HttpGet("{id:guid}")]
    public async Task<ActionResult<UserResponse>> Get(
        Guid id,
        CancellationToken cancellationToken)
    {
        var user = await service.GetAsync(id, cancellationToken);
        return user is null ? NotFound() : Ok(user);
    }

    [HttpGet("active")]
    public async Task<ActionResult<IReadOnlyList<UserResponse>>> GetActive(
        CancellationToken cancellationToken)
    {
        var users = await service.GetActiveAsync(cancellationToken);
        return Ok(users);
    }

    [HttpPost]
    public async Task<ActionResult<UserResponse>> Create(
        CreateUserRequest request,
        CancellationToken cancellationToken)
    {
        var user = await service.CreateAsync(request, cancellationToken);

        return CreatedAtAction(
            nameof(Get),
            new { id = user.Id },
            user);
    }
}
```

`[ApiController]` 協助 request binding 與 validation response；`ActionResult<T>` 允許同一個 action 回傳 `200 OK`、`404 NotFound` 或 `201 Created`；controller 不處理 repository 細節。

### `Program.cs`：composition root

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddProblemDetails();
builder.Services.AddExceptionHandler<UserExceptionHandler>();

builder.Services.AddSingleton<IUserRepository,
    InMemoryUserRepository>();
builder.Services.AddScoped<IUserService, UserService>();
builder.Services.AddSingleton<IClock, SystemClock>();

var app = builder.Build();

app.UseExceptionHandler();
app.MapControllers();

app.Run();
```

`InMemoryUserRepository` 為了讓範例不依賴 SQL Server 而使用 singleton；在真實 EF Core 專案中通常改成 `AddDbContext<AppDbContext>()`，讓 `DbContext` 以 scoped lifetime 管理。

`UserExceptionHandler` 把 service 的 `ArgumentException` 轉成 400 `ProblemDetails`；未處理的例外仍由 `UseExceptionHandler()` 回 500。實際送出全空白 `Name` 時回應是：

```text
HTTP/1.1 400 Bad Request
Content-Type: application/problem+json
{"type":"https://tools.ietf.org/html/rfc9110#section-15.5.1","title":"Request validation failed.","status":400,"traceId":"..."}
```

## 4. 實務範例：加入 EF Core 與外部 HttpClient

### EF Core repository 的核心 query

```csharp
public sealed class EfUserRepository(AppDbContext db)
    : IUserRepository
{
    public Task<User?> FindByIdAsync(
        Guid id,
        CancellationToken cancellationToken)
        => db.Users.SingleOrDefaultAsync(
            x => x.Id == id, cancellationToken);

    public async Task<IReadOnlyList<User>> GetAllAsync(
        CancellationToken cancellationToken)
        => await db.Users
            .OrderBy(x => x.Name)
            .ToListAsync(cancellationToken);

    public void Add(User user) => db.Users.Add(user);

    public Task SaveChangesAsync(CancellationToken cancellationToken)
        => db.SaveChangesAsync(cancellationToken);
}
```

注意：`SingleOrDefaultAsync` 會表達「id 應該最多只有一筆」的 domain assumption；`ToListAsync` 是把 `IQueryable` 執行成 SQL 的 boundary。

### typed HttpClient adapter

```csharp
using System.Net;

public sealed record RiskResponse(bool IsBlocked);

public sealed class RiskClient(HttpClient client)
{
    public async Task<RiskResponse?> GetAsync(
        Guid userId,
        CancellationToken cancellationToken)
    {
        using var response = await client.GetAsync(
            $"risk/users/{userId}", cancellationToken);

        if (response.StatusCode == HttpStatusCode.NotFound)
        {
            return null;
        }

        response.EnsureSuccessStatusCode();
        return await response.Content.ReadFromJsonAsync<RiskResponse>(
            cancellationToken);
    }
}

// Program.cs
builder.Services.AddHttpClient<RiskClient>(client =>
{
    client.BaseAddress = new Uri(
        builder.Configuration["RiskApi:BaseUrl"]!);
    client.Timeout = TimeSpan.FromSeconds(3);
});
```

如果 service 同時需要 DB 與 risk API，可以把 `RiskClient` 注入 service；`GetFromJsonAsync` 遇到 404／5xx 會丟 `HttpRequestException`，上面的 `GetAsync` 才把 404 轉成 `null`，其他 status code 仍拋例外。timeout 會丟 `TaskCanceledException`，retry 需依第 10 章的 resilience 設定處理。

### JSON output

```json
{
  "id": "5bb7d8d2-1d84-4b4b-9c83-6bde7b7b8301",
  "name": "Ada",
  "createdAt": "2026-09-08T10:30:00+00:00"
}
```

這個 response 是 `UserResponse` 經由 ASP.NET Core 預設 `System.Text.Json` output formatter 產生的；controller 不需要手動呼叫 `JsonSerializer.Serialize`。`createdAt` 的小數秒會依實際 `UtcNow` 而變動，下面只展示格式。

## 5. 常見誤解

- in-memory repository 只為了讓範例不需要 SQL Server；production 的 DB context 仍應由 scoped lifetime 管理。
- JSON property 名稱由 ASP.NET Core web defaults（camelCase）與 serializer options 決定，與 `record UserResponse` 無關。
- controller 注入 service 不代表 service 可以任意呼叫 `HttpContext`; domain / application code 應優先以明確 parameter 表達資料與 cancellation。
- 對 `IQueryable<T>`，`ToList()` 與 `ToListAsync()` 都會執行查詢，差別是同步或非同步；本章 service 裡的 `ToList()` 是對已 materialize 的 `IReadOnlyList<User>` 做 LINQ to Objects，不會再查 DB。
- `IReadOnlyList` 只縮小 API，不會自動做 deep immutable copy。

## 6. 面試怎麼回答

> 我會讓 controller 負責 HTTP concerns：route、status code、request binding；service 負責 use case、domain validation 與 DTO mapping；repository 負責資料來源。各層透過 interface 與 constructor injection 組合，async method 一路傳 `CancellationToken`。EF Core query 留在 `IQueryable` 到 `ToListAsync` 才執行，API 對外回傳 DTO 而不是 entity，最後由 ASP.NET Core 的 `System.Text.Json` 自動序列化。

## 7. 小練習

1. 增加 `DELETE /api/users/{id}`，設計它要回傳 `204`、`404` 或哪種 status。
2. 把 in-memory repository 改成 EF Core repository，指出 `ToListAsync` 執行點。
3. 對 `GET /api/users/active` 加上 pagination，避免一次回傳無限筆資料。

## 執行範例

```bash
dotnet run --project examples/UserApi
curl -H 'X-Demo-User: ada' \
  http://localhost:5000/api/users/00000000-0000-0000-0000-000000000001
curl -H 'X-Demo-User: ada' -H 'X-Demo-Permission: users.read' \
  http://localhost:5000/api/users/active
curl -X POST http://localhost:5000/api/users \
  -H 'X-Demo-User: ada' \
  -H 'Content-Type: application/json' \
  -d '{"name":"Grace","phoneNumber":null}'
```

這個範例沒有 `launchSettings.json`，Kestrel 預設聽 `http://localhost:5000`；若自行加入 `launchSettings.json`，以該設定為準。
